What's missing or questionable — ranked by how much they'd move the number
1. Returns don't reduce revenue/COGS (biggest gap). I flagged this when I built it, and it's still unresolved: when a customer or you return goods, total_invoice_revenue/total_invoice_cogs/total_gross_profit stay frozen at their original confirm-time values. Only separate running totals (total_customer_returns_value/cogs) track the return itself. Right now nothing subtracts those from gross profit — so gross profit is overstated by the value of any returns.

2. No salary/payroll tracking at all. I checked — there's no employee/salary/payroll model anywhere in the codebase. If you have staff, wages are usually one of your largest operating costs, and right now the only way to capture them is manually logging each payment as a generic Expense. That works, but there's no dedicated tracking (no per-employee history, no recurring/monthly structure).

3. A real structural question about GST inside COGS/revenue. This is subtle but matters: your FIFO cost basis (PurchaseItem.total_price) is tax-inclusive — it includes GST paid to the supplier and is reduced by WHT withheld. Your invoice grand_total is the same — tax-inclusive on the sale side. That means total_gross_profit isn't a clean pre-tax margin; it's contaminated by GST/WHT mechanics on both sides, which don't cleanly cancel out (different rates, WHT direction, etc.). It's currently a defensible cash-basis approximation — especially since you're not FBR-registered yet — but if you ever do register and start actually filing, this would double-count GST (once as inflated revenue/COGS, once in the separate tax ledger) unless it's redesigned to use tax-exclusive figures for profit.

4. No fixed-asset depreciation. Shelving, POS equipment, a delivery vehicle, etc. — if you own meaningful equipment, its cost isn't spread over time anywhere. Might be immaterial for your store; worth a quick gut-check rather than building unless it matters.

5. Owner's personal drawings vs. investor withdrawals. If you (the owner) ever pull cash out for personal use without going through the Investor model, that's currently indistinguishable from "lost cash" in the system — there's no dedicated "owner drawings" category.

None of these need fixing right now — you explicitly said "for now, just track gross profit and worry about actual profit later." I'm listing them so nothing surprises you when that day comes.
